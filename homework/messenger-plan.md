# Мессенджер — план проекта

## Что получится на выходе

Полноценный браузерный мессенджер с end-to-end шифрованием и аудио звонками. И учебная игрушка, и приложение с реальной архитектурой:
сообщения не читает никто, кроме участников разговора — включая сервер.

- Личные и групповые чаты
- Передача файлов
- Аудио звонки прямо в браузере, без посредников
- Видео звонки, если захочется
- E2E шифрование для личных переписок
- Работает в любом браузере, без установки
- Можно запаковать в десктоп приложение через Electron, можно пробовать мобильное через Progressive Web App

---

## Технологии по ходу

| Блок | Что трогаем |
|------|-------------|
| Real-time | Supabase Realtime — Broadcast и Postgres Changes (CDC) |
| База данных | Supabase Postgres — запросы прямо из браузера через JS клиент, RLS вместо backend API |
| Аутентификация | Supabase Auth |
| Шифрование | Web Crypto API (`SubtleCrypto`) — встроен в браузер, без библиотек |
| Хранение ключей | IndexedDB — бинарные ключи в браузере |
| Передача файлов | Supabase Storage + шифрование на клиенте |
| Аудио звонки | WebRTC — `RTCPeerConnection`, STUN/ICE |
| Сигнальный сервер | Supabase Realtime (offer/answer/ICE через каналы) |
| Фронтенд | React + Vite, TypeScript |

## Уроки

**Урок 1 — Живой чат за один вечер**
Supabase Realtime Broadcast. Никакой базы данных, никакой авторизации — открываешь два браузера и общаешься в реальном времени. Сообщения эфемерные: закрыл вкладку — история исчезла.

**Урок 2 — Сообщения в базе данных**
Переходим с Broadcast на Postgres Changes. Сообщения теперь хранятся, история не теряется при перезагрузке. Разбираем разницу между двумя механизмами Supabase Realtime.

**Урок 3 — Авторизация и личные чаты**
Auth.js или Supabase Auth. Пользователи, приватные разговоры. Только участники видят свои сообщения — Row Level Security в Postgres.

**Уроки 4–5 — E2E шифрование**
Web Crypto API: генерация ключевых пар ECDH, обмен публичными ключами через БД, шифрование AES-GCM. Сервер хранит только зашифрованный текст. Ключи живут в IndexedDB на устройстве.

**Урок 6 — Групповые чаты**
Групповой симметричный ключ. Каждый участник получает его зашифрованным своим публичным ключом. Обсуждаем ограничения по сравнению с Signal Protocol.

**Урок 7 — Передача файлов**
Файлы как зашифрованные бинарные данные. Загрузка в Supabase Storage, расшифровка на клиенте. Стриминг чанками — то, что уже умеем.

**Уроки 8–9 — Аудио звонки**
WebRTC: signaling через Supabase Realtime, STUN серверы, offer/answer/ICE. `RTCPeerConnection`, медиастримы, UI звонка.

**Урок 10 — Файлы P2P через WebRTC**
`RTCDataChannel` — передача файлов напрямую между браузерами, без сервера. Прогресс-бар, отмена, большие файлы чанками.

## Осознанные ограничения

- Приватный ключ хранится только на текущем устройстве — смена устройства означает потерю истории (как в оригинальном Signal до появления бэкапов)
- Нет key rotation — упрощение для учебного проекта
- TURN серверы для WebRTC — за рамками курса (нужны для работы за строгим NAT)
